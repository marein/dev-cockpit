# e2e runners

Executable Playwright runners, one file per feature. Each script carries its own
what and why in a header comment (purpose, routes, custom elements, gotchas) and its
checks as descriptive names, so this is the single source of truth (no separate
markdown spec). Shared helpers are in `lib.js`. Mobile and desktop divergence is
covered inside the feature that owns it, mainly `terminal.js` and `coders.js`.
A runner past the line limit hands new checks to a sibling module it requires,
which runs nowhere on its own (`projects-tags.js` for `projects.js`,
`editor-git-compare.js`, `editor-git-compare-worktree.js` and `editor-git-scroll.js` for `editor-git.js`,
`editor-preview-gfm.js` for `editor.js`,
`statusline-bounds.js` and `statusline-bar.js` for `statusline.js`,
`file-mention-links.js` for `file-mention.js`, `song-player-genres.js` for
`song-player.js`, `editor-comments-guest.js` for `editor-comments.js`, `file-links-touch.js` for `file-links.js`, `split-sheet.js` for `split.js`, `terminal-tabs-switcher.js` and `terminal-tabs-new-menu.js` for `terminal-tabs.js`, `project-share-guest.js` and `project-share-comments.js` for `project-share.js`, whose `guestPage` `assistant-share.js` borrows, `assistant-choices.js` for `assistant.js`, `events-older.js` for `events.js`).

The scripts drive throwaway instances only, create their own scratch project plus
sessions and shells, and delete everything they create, tags included: a tag
outlives its projects, so a runner removes the tags it made (`L.removeTags`). Never attach to a session
you did not create. Destructive selectors (resume, delete, stop) on shared pages
like /projects MUST be scoped to the runner's own project row
(`#project-<scratch>`); the page lists the real projects' stored coders
too, and an unscoped `.first()` deletes someone's session store.

## Run

Build the runner image once (Playwright base plus a global `playwright-core`, see
`Dockerfile`), then a run needs no install and no `node_modules`:

```bash
docker build -t dc-e2e:1.60.0 - < tests/e2e/Dockerfile   # once
docker run --rm --add-host=host.docker.internal:host-gateway \
  -e BASE_URL=https://host.docker.internal:3010 [-e ENGINE=...] [-e CHECK=...] \
  -v "$PWD/tests/e2e":/work -w /work dc-e2e:1.60.0 node <feature>.js
```

The browser runs in the container's own network namespace and reaches the
instance, which listens on `0.0.0.0`, over the host gateway. Under
`--network host` it shares the host's interfaces, and every container start
that adds or drops an addressed interface there (a compose up, another
session's language server) makes Chromium abort what is in flight with
`net::ERR_NETWORK_CHANGED`. Only a runner whose own server the instance has
to reach on loopback (the webhook receiver of `notifications.js`, the Ollama
server of `ollama.js`) or that maps a name onto loopback
(`editor-copy-path.js`, `editor-lsp-class-name.js`) needs `--network host`.
`project-share.js` composes stacks of its own while it runs, so it publishes
its server on the host's loopback instead.

`BASE_URL` defaults to `https://localhost:3010`. `ENGINE` defaults to `chromium`;
set `webkit` or `chromium,webkit` for the cross-browser (Chrome plus Safari) pass.
`CHECK` narrows a run to the checks whose name contains one of a comma
separated list of substrings (case insensitive), matched against the name
`run(...)` is called with; unset runs the whole file. It still needs the
instance and the fixture the feature's own row below asks for, so it saves
the checks either side of the ones under work, not the setup, and a check
that reads state an earlier one built (a `let` the file sets before its own
`run`) names that earlier one alongside it, comma separated, or it finds
nothing there. The only dependency is `playwright-core`, baked into the image
(browser drivers need it; there is no stdlib equivalent that also covers
WebKit/Safari).

## Instances a full run needs

Throwaway instances per the shared setup, each with its own `--state-dir` and cookie
name. `--provider` is deprecated and ignored, every instance serves all coders whose
CLI is installed on the host. Most scripts run against the instance on `:3010`
(cookie `tc_session`), including `coder-claude.js` and `multi-coder.js`.
`coder-claude.js`, `coder-rename.js` and `terminal-copy.js` drive the real
claude CLI, which keeps its login in `HOME`, so their instance runs with the
`HOME` of the user claude is logged in for. Under a scratch `HOME` claude
comes up on its login menu, and the runners stop there with `claude asks for
a login` (`L.assertNoLogin`). Never copy or link that login into a scratch
`HOME`: claude rotates its refresh token, and a second holder that refreshes
logs every other claude out. The runners leave claude's transcripts and the
folder trust of their scratch projects in that `HOME`. Copilot and opencode
need no login for what `coder-rename.js` and `coder-opencode.js` do, both
keep `XDG_DATA_HOME` on a scratch directory.
Extra instances:

- one on `:3012` started with `DEV_COCKPIT_UPDATE_API_URL` pointing at a stub
  returning a GitHub shaped `v999.0.0` release whose asset is this tree built
  with `-ldflags "-X main.version=999.0.0"`, packaged as
  `dev-cockpit_v999.0.0_linux_amd64.tar.gz` (tar.gz with a file named `dev-cockpit`)
  plus `dev-cockpit_v999.0.0_checksums.txt` (`<sha256>  <asset name>`), for
  `update.js MODE=available`. The env var reaches only a dev build, one whose
  `main.version` stayed `dev`: a release build ignores it and reads the feed
  URL baked in at build time, so the serving instance must be a plain dev
  build. The `999.0.0` asset binary is a release build by that rule and
  ignores the env var after the swap, which the runner tolerates, it only
  reads `current` from the re-execed instance. The release body has to carry
  the words `Stub release`, the changelog check reads the notes out of the
  dialog and matches them against `/Stub release/i`. The apply test asserts
  that the instance re-execs as `999.0.0`, so the version must really be baked
  in. Apply swaps the binary in place, the instance must run its own copy,
  never the repo build.
- one on `:3013` with the stub URL returning `[]`, for `update.js MODE=uptodate`.
- one on `:3017` for `update.js MODE=gitlab`: the same shape as `:3012`, but
  the instance binary is built with `-ldflags "-X main.updateFeedFormat=gitlab"` (and
  no `-X main.version`, it has to stay a dev build for the env var) and the
  stub answers the GitLab releases JSON instead: an array of objects with
  `tag_name`, `name`, `description` (the notes, carrying `Stub release`),
  `released_at`, `upcoming_release` and `assets.links[]` entries with `name`
  and `direct_asset_url` pointing at the same `v999.0.0` archive and checksums
  files.
- `assistant.js` and `wake.js` need their own instance with `tests/e2e/fakes`
  ahead of the real CLIs on `PATH` and `HOME` pointing at a scratch directory.
  Only those two runners belong on it: the fakes never persist an interactive
  session, so the terminal driven runners (frontend, terminal) fail
  there for reasons that have nothing to do with the app. The fakes speak
  the documented claude and copilot machine protocols, persist a minimal
  provider session so the cockpit can resume it, and never spend a model

## Notes

- **A create opens the dialog, so the page under it does not change.** A
  `waitForURL` for the landing matches the page it started on when that already
  fits the pattern and resolves before the create happened: read the URL before
  the submit and wait for a different one. Bootstrap ignores a `hide()` during
  the show transition, so give a dialog its fade (~600ms) before Escape or
  submit, and wait for `dc-form-modal` to upgrade before clicking a trigger.
- `page.waitForFunction` does not await an async predicate: the returned
  promise is always truthy and the wait resolves at once, on both polling
  modes. A wait that has to fetch something polls from the Node side instead
  (an `evaluate` in a loop, see `waitNotify` in `docker.js`).
- **WebKit's network process can crash under a navigation.** Playwright
  1.60's WebKit sometimes corrupts its heap in libsoup when a navigation
  cancels the loads a page still has in flight, and aborts its network
  process. The run shows `WebKit encountered an internal error` on a `goto`,
  or the context's cookies are gone and the next page lands on `/login`;
  with `DEBUG=pw:browser` the browser's stderr names
  `soup_session_feature_request_unqueued` and `corrupted double-linked
  list`. It happens with HTTP/2 and HTTP/1.1 alike and says nothing about
  the app.
- Runs report a non-gating `cdn noise` count (the editor's CodeMirror packs
  throttled by their third-party CDN, plus WebKit's "due to access control
  checks" page error for the /events, /update/check and editor terminals
  fragment background requests a navigation aborts mid-flight); only
  app-origin console and page errors gate. Rationale and filters live in
  `lib.js` (`isCdnNoise`, `isWebkitAbortNoise`).
